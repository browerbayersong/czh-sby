# EDA Agent 使用说明（v8.3）

本包在 **EDA Agent v8.2** 基础上增加了自动纠错闭环（StateGraph）、覆盖率采集、网页结果分析与导出。
适用环境：Windows（运行 Agent 与网页）+ Linux 虚拟机（运行 VCS）。

---

## 1. 环境准备

### 1.1 Python

建议 3.10+，本包在 **Python 3.13.9** 上验证通过。

```powershell
cd <本包目录>\code
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r ..\requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

主依赖包含网页和 SSH 所需的 Streamlit、Paramiko。Studio/Jupyter 等可选开发工具
通过 `..\requirements-dev.txt` 另外安装。

依赖版本（已验证组合）：

| 包 | 版本 |
| --- | --- |
| langgraph | 1.2.16 |
| langchain | 1.4.6 |
| langchain-openai | 1.7.2 |
| python-dotenv | 1.2.4 |
| streamlit | 1.66.0 |
| paramiko | 3.5.1 |
| grandalf | 0.8 |

### 1.2 配置 `.env`

把 `..\.env.example` 复制到 `code\` 目录下并改名为 `.env`，填入真实密钥：

```dotenv
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-pro

# 虚拟机地址（DHCP，重启后可能变化）
EDA_SSH_HOST=192.168.81.128
EDA_REMOTE_BASE=/home/IC/Desktop/EDA_Projects

# 可选：指定聊天与工程数据目录；留空时使用程序默认目录
EDA_DATA_DIR=
```

> `.env` 含密钥，**不要提交到仓库、不要外发**。

新机器的默认数据目录为项目下的 `data/`，已有 `C:\LangGraph_talk` 时继续使用旧目录。
没有密钥时仍可执行离线测试和 `python verify_evidence.py`；真正生成代码或提出修复补丁时才会调用模型。

### 1.3 Linux 侧准备

| 项 | 要求 |
| --- | --- |
| 登录用户 | `IC`（普通用户，**不要用 root**） |
| 工程根目录 | `/home/IC/Desktop/EDA_Projects`（可改，须在用户家目录内） |
| 工具 | `/opt/Synopsys/VCS2014/bin/vcs`、`.../urg` |
| SSH | 22 端口可达；首次需人工核验主机指纹 |

第一次连接前，在 **Windows** 上执行一次并接受指纹：

```powershell
ssh -o HostKeyAlgorithms=+ssh-rsa IC@192.168.81.128
```

这一步会把主机密钥写入 `C:\Users\<你>\.ssh\known_hosts`，v8.2+ 的 Paramiko 只信任该文件里的密钥。

## 2. 启动网页

```powershell
cd <本包目录>\code
.\venv\Scripts\streamlit.exe run web_app_eda_v8.py --server.headless true --server.port 8501
```

浏览器打开 `http://localhost:8501`。

### 2.1 页面上的四个按钮

| 按钮 | 作用 | 是否跑仿真 |
| --- | --- | --- |
| ① 测试 SSH | 检查身份、家目录、三个 EDA 工具路径 | 否 |
| ② 上传工程版本 | 把已批准文件上传为 `runs/upload_001` 快照 | 否 |
| ③ VCS 编译仿真 | 新建 `runs/vcs_NNN` 快照并跑编译 + 仿真 + 覆盖率 | 是 |
| ④ 自动纠错闭环 | 失败 → DeepSeek 补丁 → 新快照重跑，最多 N 轮 | 是（多轮） |

### 2.2 顺序

1. 新对话 → 描述需求 → 等 Agent 生成 → 点 **「确认保存本任务全部文件」**（不审批不会上传）；
2. 填 IP / 用户 / 密码 / 工程名 / TB 顶层，点 **①**；
3. 点 **②** 上传，再点 **③** 仿真；
4. 失败时点 **④**，在「自动纠错闭环结果」里看轮次、补丁 diff，确认后点「采纳」写回 `generated/`。

### 2.3 结果分析面板

SSH 面板下方的 **「📊 结果分析（本对话）」**：

- 指标卡：运行次数、通过率、最新覆盖率（较基线增量）、检查点
- 逐轮明细表 + 覆盖率折线 + 检查点柱状图
- 失败轮次的 `exp/got` 模式
- 逐轮明细含**通过数、场景数、种子数、功能覆盖 bins、结束标记**
- **「⬇️ 导出分析摘要（Markdown）」**：生成可直接粘进报告的表格

数据只读本地 `chat.json` 与日志，不连虚拟机。

### 2.4 编译配置（可选）

在聊天工作空间根目录放 `compile_cfg.json` 可显式控制 VCS 编译内容（不放则自动扫描）：

```json
{
  "filelist": ["files.f"],
  "defines": {"WIDTH": "8"},
  "incdirs": ["generated/rtl/inc"],
  "tb_top": "tb_fifo_sync",
  "options": ["+lint=all"]
}
```

- `.f` 在本地展开，支持 `+incdir+` / `+define+` / `//` 与 `#` 注释，不会被上传
- 路径必须是工作空间内的相对路径；源码必须已在上传列表里
- `options` 仅允许 `-sverilog`、`+v2k`、`-timescale=1ns/1ps`、`+lint=all`、`+lint=context`

### 2.5 运行历史

页面下方「📜 运行历史」可按轮次查看：状态、退出码、覆盖率、源文件列表、编译配置、
每轮源码的 SHA-256，以及编译/仿真日志下载。

哈希来自每轮运行目录里的 `snapshot_manifest.json`（`remote_job` 会自动保存到本地）；
老轮次若缺失，可用 `fetch_evidence.py` 回填。

## 3. 命令行方式

### 3.1 离线回归（不连虚拟机）

```powershell
cd <本包目录>\code
.\venv\Scripts\python.exe test_v8_2_offline.py
```

预期三条 `PASS`：上传/两轮 VCS/快照隔离、路径与符号链接规则。

### 3.2 自动纠错闭环验收

准备一个工作空间，结构必须含 `generated\rtl\*.v` 与 `generated\tb\*.v`：

```powershell
$env:EDA_COVERAGE='0'      # 闭环多轮重跑时建议关覆盖率，见 §4
.\venv\Scripts\python.exe autofix_cli.py --workspace <工作空间> --project <远端工程名>
```

运行时提示输入 `IC` 的 SSH 密码（不回显）。进度同时写入 `<工作空间>\autofix.log`。

---

### 3.3 换一个工程跑一次 VCS

```powershell
.\venv\Scripts\python.exe -u run_vcs_once.py --workspace <含 generated/ 的目录> --project <新工程名> --tb <TB 顶层模块>
```

用于验证工程通用性或临时调试，例：

```powershell
.\venv\Scripts\python.exe -u run_vcs_once.py --workspace ..\designs\fifo --project fifo_test --tb tb_fifo_sync
```

注意：工程名不能是保留名（`adder` / `ref` / `mw_lib` 等），且同一工程目录只能被一个 chat 占用；换工程时 TB 的输出格式要符合 `[PASS]` / `[FAIL]` / `TEST PASSED` 约定，否则会被记为 `finished_unverified`。

### 3.4 归档远端快照（用于离线复核 SHA-256）

```powershell
.\venv\Scripts\python.exe -u fetch_evidence.py --labels vcs_004,vcs_006,vcs_007,vcs_015,vcs_017
```

脚本按 `snapshot_manifest.json` 只下载源码文件（`src/` 下混有的 `csrc/`、`cm.log`、`ucli.key`
等 VCS 编译产物会被跳过），落到 `evidence/<project>/<label>/`，并逐个校验 SHA-256。

### 3.5 验收 P2 完成度

```powershell
.\venv\Scripts\python.exe verify_p2.py
```

脚本逐项输出 PASS/FAIL，并把结果写入 `report/P2_验收结果.txt`：

| 检查项 | 判定方式 |
| --- | --- |
| 五套离线测试 | 子进程运行，退出码必须为 0 |
| 工具路径配置化 | 设置 `EDA_VCS_BIN` / `EDA_URG_BIN` 后导入模块，断言生效 |
| 运行历史 SHA-256 | 读取会话历史，统计带 `snapshot_manifest.json` 的轮次 ≥3 |
| 历史详情可读 | `load_run_detail` 能读出状态、清单与日志文件 |
| 前端异常缓解 | `web_app` 中存在 `st.fragment(_log_viewer)` 且带回退分支 |
| 换工程可用 | `evidence/` 下 FIFO / 加法器 / 计数器都有 `passed_by_marker` |

全部 PASS 才返回 0；有任何 FAIL 返回 1，可直接接进 CI。

### 3.6 验收 P0 闭环能力

```powershell
.\venv\Scripts\python.exe verify_p0.py
```

11 项自动判定：StateGraph 结构、LoopState 字段、四条条件边、五类失败分类、
「采纳只写变化文件」、两个故障案例的失败轮→修复轮状态、每轮记录字段。

结果写入 `report/P0_验收结果.txt`；全 PASS 返回 0。

## 4. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `SSH 连接失败（IC@x.x.x.x:22）：TimeoutError` | 虚拟机 IP 变了，或 VM 没启动 | 在 VM 里跑 `ip -4 addr show eth0`，改网页 IP 与 `.env` 的 `EDA_SSH_HOST` |
| `SSH 认证失败` | 密码不对 / 用户不是 IC | `passwd IC` 重设；不要用 root |
| `无可用认证方法` | 密码框留空 | 填密码，别留空 |
| `host key` 相关错误 | 换了虚拟机或重装系统 | 删掉 `known_hosts` 里对应行，重新 `ssh` 接受一次 |
| `UnicodeDecodeError: 'gbk'` | 中文 Windows 下 `langgraph dev` 读文件 | 设 `$env:PYTHONUTF8='1'` |
| 仿真 `fatal signal` | VCS 2014 在 `-cm` 收尾阶段偶发崩溃 | 设 `$env:EDA_COVERAGE='0'` 关覆盖率；不是设计错误 |
| 页面 `removeChild` 红字 | Streamlit 前端 DOM 冲突 | 关浏览器自动翻译、`Ctrl+F5`；不影响后台结果 |
| 端口 8501 被占用 | 上一个进程没退 | `Get-NetTCPConnection -LocalPort 8501`，结束对应进程 |
| 控制台「卡住」无输出 | Windows 控制台进入选择模式，阻塞 stdout | 取消「快速编辑模式」，或另开窗口 `Get-Content autofix.log -Wait` |
