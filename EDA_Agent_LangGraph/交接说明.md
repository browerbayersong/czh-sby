### 1.3 工程通用性验证（三个设计）

为验证流水线不是只对计数器写死，另做了两个结构完全不同的设计：

| 项 | 计数器 | 同步 FIFO | 256 位加法器 |
| --- | --- | --- | --- |
| 远端工程 | `counter_v82` | `fifo_sync_v1` | `cla256_v1` |
| RTL 文件数 | 1 | 1 | **6（4 层层次）** |
| 总源文件 | 2 | 2 | **7** |
| 检查点 | 1032 | 351 | **1005** |
| 覆盖率总分 | 93.05% | 96.61% | **99.47%** |
| 判定 | passed_by_marker | passed_by_marker | passed_by_marker |

- **FIFO**：状态型设计（读写指针、满/空、同时读写仲裁），源码在 `designs/fifo/`，日志 `evidence/fifo_sync_v1/`。
- **256 位加法器**：`top_adder → CLA_256 → CLA_64/16/4/3_C` 四层、7 个源文件，由 `source_manifest` 自动收集，**不依赖手写 filelist**。RTL 来自本机实验工程 `D:\adder`，未随包分发，仅保留日志 `evidence/cla256_v1/`。

两个设计都先在本地 **ModelSim** 跑通（FIFO 351 检查点、加法器 1005 检查点），再进 VCS，均一次通过。过程中本地仿真先后抓到 TB 自身的 delta 时序缺陷与判定格式不匹配——说明「换设计」时最需要适配的是**测试平台约定**，而不是流水线代码。

## 2. 架构与关键决策

```
Streamlit（网页）
  ├─ 生成层 StateGraph：inspect → plan → make → review → repair → final
  │    产出草稿 → 人工审批落盘
  └─ 闭环层 StateGraph：stage → simulate → analyze → patch → stage / finalize
       消费已批准源码 → 产出补丁建议 → 人工采纳写回
                    │
        SSH/SFTP（Paramiko，固定命令模板）
                    ↓
        Linux 虚拟机：VCS 2014 + urg，每轮独立快照 runs/vcs_NNN
```

| 决策 | 理由 |
| --- | --- |
| 每轮独立快照，禁止覆盖 | 迭代记录必须可复核 |
| 补丁只写 `shadow/iter_NN` | 不污染已批准的 `generated/` |
| 远程只跑固定命令模板 | 阻止模型生成的 `rm -rf` 等任意 shell |
| 环境错误（license/网络/崩溃）不改 RTL | 改代码没有意义，且会伪造因果 |
| 断言失败禁止改 Testbench | 防止通过放宽检查「骗过」测试 |
| 生成与闭环分成两张图 | 中间是人工审批边界（见第 6 节） |

## 5. 已知问题与限制

1. **两张图未合并**：生成层与闭环层靠 `run_autofix()` 串联。若严格要求「五阶段在同一张图」，需定义父图状态并用 `add_node(subgraph)` 合并（约 0.5~1 天）。
2. **覆盖率与闭环互斥**：VCS 2014 在 `-cm` 收尾偶发 `fatal signal`（虚拟机资源充足，非磁盘/内存问题）。闭环多轮重跑时用 `EDA_COVERAGE=0`。
3. **分支覆盖卡 80%**：TB 的两条错误处理路径只在断言失败时执行，测试全过必然不覆盖，属正常现象。
4. **IP 是 DHCP**：虚拟机重启可能换地址，需同步改 `.env` 的 `EDA_SSH_HOST`（网页默认值也读它）。
5. **闭环运行不写会话历史**：④ / CLI 的运行不进 `chat.json` 的 `remote_history`，排查看 `shadow/` 或 `autofix.log`。
6. **Python 版本**：交接文档原建议 3.10.11，本包在 3.13.9 验证通过。
7. **`removeChild` 前端异常**：勾选日志时偶发，关掉浏览器自动翻译可缓解，不影响后台。

## 6. 为什么分成两张图

课设要求「定义 StateGraph 节点（需求解析→代码生成→仿真执行→结果分析→迭代纠错）」。本项目把前两阶段放在生成图，后三阶段放在闭环子图，中间夹一道**人工审批**：

- 生成层产出的是草稿，未经确认不能上传到 Linux；
- 闭环层产出的是补丁建议，未经确认不能写回已批准文件。

这是交接文档反复强调的安全边界。代价是「五个阶段不在一张图里」，答辩时需要说明取舍；若老师坚持要单图，按第 5 节第 1 条改造。

## 10. 交接红线

1. **不要转发 `.env`、SSH 密码、API Key**；新机器上由有权限的人重新配置。
2. **不要用 root 登录 Agent**，全程 `IC`。
3. **不要覆盖旧工程** `adder` / `ref`（代码里 `REMOTE_DENIED_DIRS` 已强制拒绝）。
4. **不要执行模型生成的 `.sh/.tcl`**，远程只走固定命令模板。
5. **不要伪造通过**：`finished_unverified` 不等于通过，覆盖率不能靠制造失败来刷。
